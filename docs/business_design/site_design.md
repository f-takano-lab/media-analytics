# Site Design

deepintoanalytics.com のサイト設計。サイトの立ち位置(Site Identity)、コンテンツの構造、URL、運営ポリシーを定める。

---

## 1. Site Identity

### 基本情報

| 項目 | 値 |
|---|---|
| サイトタイトル | Deep into Analytics |
| 正規ドメイン | deepintoanalytics.com |
| サブタイトル | 数学・統計学・ミクロ経済学をベースに、ビジネスの意思決定を分析する |

### コンセプト

高校数学すら危うかった29歳文系未経験者が、約4年に及ぶ数学・統計学・ミクロ経済学の独学を経て、ビジネスデータアナリストとして自立を目指す過程と、その中で得た理論・分析・実装・意思決定の知見を公開するメディア。

### ターゲット読者

1. 数学・統計学・ミクロ経済学・計量経済学等を学習している人
2. これらの分野を応用して、実務のビジネスデータ分析に取り組んでいる人、取り組みたいと考えている人
3. ビジネス(特に Web マーケティング)の意思決定において、定量的・科学的なアプローチに関心がある人

### USP

| 方針 | 内容 |
|---|---|
| 大きな地図の提示 | 個別の概念・理論・実装を、一本の幹でつながった全体像として示す。 |
| 行間の補完と言語化 | 独学者がつまずいた箇所を、教科書の行間まで埋めて言語化する。 |
| 理論と実践へのコミット | データ分析の理論と実践だけを、深く・詳細に扱う。 |

### 編集方針

| 対応する USP | 規則 |
|---|---|
| 大きな地図の提示 | 定義・定理・数式・SQL・分析手法を孤立した知識として扱わず、互いの関係を示す。細部は全体像を支える手段として扱う |
| 大きな地図の提示 | 小学校算数・初等的な直観と、大学数学を接続する |
| 行間の補完と言語化 | 運営者自身の学習ノートを基礎素材とし、編集・推敲したものに限って公開する。AI の出力をそのまま記事にしない |
| 行間の補完と言語化 | 数式の操作そのものではなく、なぜその定式化に至るかを説明する |
| 行間の補完と言語化 | 例題の解説では、必要に応じて G・ポリアの問題解決手法を明示する |
| 理論と実践へのコミット | 一般的なハウツー・ノウハウ系の内容は扱わない |

## 2. Content Architecture

### 2.1 サイト構造

| 区分 | URL | 役割 |
|---|---|---|
| Articles | `/articles/{slug}/` | データ分析の理論と実践に関する知見 |
| Story | `/story/` 配下 | 運営者自身のキャリアと挑戦の軌跡 |
| Profile | `/profile/` | 現時点の運営者の要約 |
| Books | `/books/` 配下 | 書籍紹介 |
| Overview | `/overview/` | サイトの目的・テーマ・運営方針 |
| Contact | `/contact/` | お問い合わせ |
| 法令ページ | — | 法令・規約にもとづく開示 |
| アーカイブ | `/category/`, `/series/`, `/textbooks/` | 該当記事の一覧 |

記事の構成は [article_structure.md](article_structure.md)、ページ同士の導線は [site_navigation.md](site_navigation.md) で定める。

### 2.2 分類軸

記事(`/articles/`)は、次の3つの分類軸を持つ。タグは当面使用しない。

| 軸 | 役割 | 1記事あたり |
|---|---|---|
| category | 記事の主題領域 | 1つ |
| series | 複数記事を時系列・企画・文脈で順序立てて束ねる | 最大1つ |
| textbook | 記事と紐づく教科書 | 最大1つ |

### 2.3 カテゴリ

| 表示名 | slug | 焦点 | 内容 |
|---|---|---|---|
| 数理基礎 | `mathematical-foundations` | 理論 | 理論そのものの理解を目的とする。代表例: 確率論、統計学、ミクロ経済学、計量経済学、最適化数学。必要に応じて、理論の理解や確認のために Python での計算実装も扱う |
| 指標・集計 | `metrics-aggregation` | 実践 | 統計解析に入る前の、指標と集計の設計、SQL による実装、観測基盤、KPI の設計 |
| 数理データ分析 | `mathematical-data-analysis` | 実践 | 統計解析・因果推論・数理モデリングを用いて、意思決定問題を定式化し分析する |

**判定基準**:記事の目的が、理論そのものを理解することなら数理基礎、データや意思決定問題に適用することなら実践側(指標・集計、数理データ分析)とする。実践側の2つは、統計解析に入る前か後かで分ける。

### 2.4 シリーズ

| 表示名 | slug |
|---|---|
| メディア分析プロジェクト | `media-analytics` |

シリーズ内の記事の順序は `published_at` で決める。

### 2.5 教科書軸

`/textbooks/` 配下に教科書単位のページを置き、教科書の行間解説記事を教科書ごとに整理する。

- 対象は、記事と紐づく教科書・専門書に限る。一般書は含めない。
- 教科書の slug には、教科書ごとに定めた略称を用いる。

### 2.6 Books

`/books/` は、読者向けの書籍紹介のセクションである。教科書・専門書に加え、運営者の分析思想の形成に寄与した一般書も扱う。

- 厳選した書籍の一覧ページを1つ設ける。
- Textbooks とは同じ書籍を扱う場合があるが、Books は読者向けの書籍紹介、Textbooks は記事の整理と回遊のための軸として区別する。

### 2.7 運用ルール

- カテゴリは頻繁に変更しない。追加・統合・名称変更を行う場合は、変更履歴を残す。
- シリーズと教科書の slug は、安易に変更しない。
- 記事の slug は、公開後に変更しない。
- 分類軸・slug・URL は分析軸として用いられるため、変更する場合は過去データとの比較や集計定義への影響を確認する。

## 3. URL 設計

| 種別 | URL |
|---|---|
| 記事 | `/articles/{slug}/` |
| Story | `/story/`, `/story/part-{n}/`, `/story/part-{n}/chapter-{m}/` |
| Books | `/books/` 配下 |
| 固定ページ | `/profile/`, `/overview/`, `/contact/` |
| カテゴリ | `/category/{category-slug}/` |
| シリーズ | `/series/{series-slug}/` |
| 教科書 | `/textbooks/`, `/textbooks/{textbook-slug}/` |

- 記事本体は `/articles/{slug}/` に1つだけ存在させ、同じ記事を複数の URL に置かない。
- カテゴリ・シリーズ・教科書は記事のメタデータとして扱い、記事の URL には含めない。カテゴリの変更が URL の変更を引き起こさないようにするためである。
- slug は、ハイフン区切りの英小文字とする。
- slug には、公開後に変わり得る情報(継続中の期間の終了年など)を含めない。

## 4. 運営ポリシー

### 掲載範囲

SEO などのサイト運営に関する話題は、分析の前提を説明するのに必要な範囲で分析記事の中で触れるにとどめ、独立した記事にはしない。運営者を紹介する役割は、`/profile/` と `/story/` だけが担う。

### 収益化

- 書籍の Amazon アフィリエイトを Books にのみ置き、記事の参考文献リストには付けない。収益額はビジネスゴールにも主要な最適化対象にもしない。
- 使っていない商品は紹介しない。
- 表示型広告は掲載しない。
- Stripe による投げ銭を受け付ける。導線の配置は [site_navigation.md](site_navigation.md) で定める。
